# コーディングフロー / 品質チェックリスト

このファイルは、実装時に毎回確認するための運用チェックリストです。  
`README.md` のルールを作業フローとして再整理しています。

## 1. 着手前（要件・設計）

- [ ] 変更対象を明確化する（HTML / CSS / JS のどこを触るか）
- [ ] ユーザーから明示された指示範囲を確定する（指示のないファイル追加・実装追加はしない）
- [ ] モバイルファーストで設計する
- [ ] 同一レイアウトはコンポーネント化する
- [ ] 追加する値がマジックナンバーにならないか確認し、必要なら `src/css/variables.css` に定義する

## 2. 実装中（命名・記述ルール）

### 命名

- [ ] 省略語を使わず、意味が明確な完全な単語を使う（例: `btn` ではなく `button`）
- [ ] CSS クラスは BEM を使う（`block__element--modifier`）
- [ ] コンポーネントは `c-`、レイアウトは `l-` プレフィックスを使う
- [ ] ID はキャメルケース、JS 変数/関数もキャメルケースで統一する

### HTML

- [ ] スタイルやスクリプトを HTML に直接埋め込まない
- [ ] ユーザビリティとアクセシビリティを意識した構造化マークアップにする

### CSS

- [ ] 可能な限り論理プロパティを使う（`inline-size` / `margin-block` など）
- [ ] モダン構文を優先する（`display` 2値構文、`translate` / `scale` など）
- [ ] `0px` ではなく `0` を使う
- [ ] `!important` は原則使わない
- [ ] スタイルで ID セレクタを使わない
- [ ] メディアクエリは `min-width: 768px` を基本とする
- [ ] プロパティ順は「レイアウト -> 見た目 -> テキスト -> アニメーション」の順を意識する

### JavaScript

- [ ] `var` は使わず、`const` 優先・必要時のみ `let` を使う
- [ ] 比較は `===` / `!==` を使う
- [ ] 文字列はシングルクォートを使う
- [ ] アロー関数の引数は常に括弧付きで書く
- [ ] ブロック文は必ず波括弧を付ける
- [ ] `debugger` を残さない
- [ ] DOM 操作は Vanilla JS（`querySelector` / `addEventListener`）を使う
- [ ] ページ共通スクリプトは IIFE でスコープを閉じる
- [ ] 非同期処理は `async/await` を優先する

## 3. 実装後（セルフレビュー）

- [ ] 変更差分を見て、命名や責務分離が崩れていないか確認する
- [ ] HTML / CSS / JS で不要コードが混入していないか確認する
- [ ] 関連ファイル間で依存関係が崩れていないか確認する（import や読み込み順）

## 4. 検証コマンド（必須）

以下を実行してから完了とする。

```bash
npm run check
```

必要に応じて個別確認:

```bash
npm run format
npm run lint:js
npm run lint:css
npm run lint:html
```

## 5. 完了条件

- [ ] Lint / Format エラーがない
- [ ] 要件を満たし、デザイン意図に沿っている
- [ ] README の規約違反がない
- [ ] 指示されていないファイル追加・余計な実装を含んでいない
- [ ] PR 前に最終差分を確認した
